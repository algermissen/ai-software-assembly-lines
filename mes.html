3. Agent / Software MES — Detailed Implementation

← Index

Architecture Overview

Execution layer that manages production orders (features, bugs, migrations), schedules resources (agents, humans, compute/tokens), enforces sequence and quality gates, tracks full genealogy, and provides plant-floor visibility. Sits above the UDN event bus and integrates with Jidoka stations.

Technology Choices

  • Core Orchestrator: Temporal workflows (one workflow per production order; durable, supports long waits for humans/agents). Alternative: Camunda BPMN processes.
  • State & Genealogy: Event sourcing into the UDN + materialized views in Postgres (current order state) and ClickHouse (analytics). Full lineage via OpenTelemetry traces linked to order_id.
  • Scheduling: Resource pool management (agent capacity, token budgets) inside Temporal activities or a dedicated scheduler service.
  • Integrations: Bidirectional with Linear/Jira (status sync), GitHub (branch/PR events), observability backends. All via UDN topics.
  • Dashboards: Grafana or custom (using the materialized views) showing order status, station queues, OEE, genealogy trees.

Defined Datapoints & Metrics

  • Production Order: id, type, priority, risk_tier, acceptance_criteria, current_station, status (queued/in_progress/blocked/complete/failed), start/end timestamps, assigned_resources, token_budget_remaining.
  • Genealogy: ordered list of events/spans (agent_session, model, prompt_hash, tool_calls, human_approvals, quality_results) with parent/child links.
  • MES KPIs: order cycle time, on-time completion rate, resource utilization, blocked time %, genealogy completeness %, quality gate pass rate per station.

Development / Operations Process Flow

  1. Intent validated and converted to production order in MES (pull from product backlog).
  2. MES schedules first station, reserves agent/compute capacity, publishes order.ready_for_station.
  3. Station executes (via agent or human); publishes progress and results to UDN; MES updates order state and genealogy.
  4. Quality gate failure or Andon → MES marks order blocked, notifies, waits for resolution event, then resumes or rework path.
  5. All stations complete + final gate pass → MES authorizes deploy (or auto if dark-factory eligible).
  6. Post-deploy monitoring events update order to "in production"; any incident can create a linked rework order with full prior genealogy.
  7. Completed orders feed SPC and Kaizen analysis.

Provides the control plane that manufacturing MES gives the shop floor: visibility, sequencing, resource management, and full traceability of every "part" (change).
