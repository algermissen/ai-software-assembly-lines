5. SPC & OEE for AI Code Production

← Back to index

Description

Treat agent sessions, pipelines, and lines as manufacturing equipment. Apply Overall Equipment Effectiveness (OEE = Availability × Performance × Quality). Availability: agent/system uptime. Performance: actual vs ideal cycle time / throughput. Quality: first-pass yield, scrap/rework rate, escaped defect rate. Statistical Process Control (SPC): control charts for key metrics (cycle time, defect rate, review time, rework). Process capability (Cp/Cpk). Detect drift early. Complement to DORA metrics adapted for AI.

Manufacturing Parallel

OEE and SPC are foundational for continuous improvement in manufacturing. They quantify equipment and process performance, enabling Kaizen.

Adversarial Assessment

Pros: Quantitative, proven manufacturing tools. Detects process degradation early. Balances throughput with quality (avoids pure volume metrics). Supports data-driven Kaizen on prompts, models, harnesses. Maps cleanly to existing DORA + rework/escaped defects.

Cons / Risks: Defining "good part" for code is more subjective than physical goods. Software variability higher than many manufacturing processes. Requires sufficient data volume. Risk of Goodhart's law / metric gaming by agents or teams. Implementation overhead.

Viability: High as overlay on any of the other concepts. Essential for scaling without quality collapse.

Team Adversarial Vote: Strongly recommended. Start with simple yield, rework, and cycle-time tracking. Expand to full SPC as volume grows.
