5. SPC & OEE for AI Code Production — Detailed Implementation

← Index

Architecture Overview

Measurement and control layer treating agent pipelines, stations, and review processes as manufacturing equipment. Collects time-series and event data from the UDN, computes OEE and SPC signals, visualizes control charts, and feeds alerts into Jidoka/Andon and Kaizen processes.

Technology Choices

  • Collection: OpenTelemetry metrics + traces from agents, Temporal, CI; events from UDN. Export to Prometheus or ClickHouse.
  • Calculation & Storage: ClickHouse or Timescale for raw events; materialize OEE and control limits in scheduled jobs or Flink/stream processing. Grafana for dashboards and alerting.
  • SPC: Standard control charts (X-bar, p-charts for yield/defect rates) implemented in Grafana or a small analytics service. Alerts when process goes out of control.
  • Integration: Out-of-control or low-OEE signals published back to UDN as andon or kaizen.candidate events.

Defined Datapoints & Metrics

OEE components (per station or line):

  • Availability = (planned time − downtime) / planned time. Downtime = agent failures, queue waits, blocked states.
  • Performance = (ideal cycle time × good units) / actual operating time. Ideal from historical or target.
  • Quality = first-pass yield = good units / total units. Good = passes all gates without rework and no escaped defect within window.
  • OEE = Availability × Performance × Quality.

Additional SPC & quality metrics:

  • Cycle time (total and per station), rework rate, escaped defect rate, review time, token cost per accepted change, confidence distribution, process capability (Cpk-style on cycle time or yield).
  • Control limits computed from stable historical periods; alerts on statistical signals (beyond 3σ, trends, etc.).

Development / Operations Process Flow

  1. Every station and agent action emits structured metrics and events into UDN/OTel.
  2. Analytics layer continuously computes rolling OEE, yields, and control charts.
  3. Dashboards give real-time plant-floor view of the software factory.
  4. Out-of-control or degrading metrics automatically raise Andon events or Kaizen candidates (e.g., "review time rising — investigate prompt or model drift").
  5. Teams use the data for targeted improvements rather than vanity velocity metrics.
  6. Baselines established pre-AI or per model version; comparisons track true process improvement.

Turns the continuous code stream into a measurable, controllable manufacturing process. Essential complement that makes the other four concepts improvable rather than anecdotal.
