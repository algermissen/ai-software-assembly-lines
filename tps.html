2. Jidoka / TPS AI Assembly Line

← Back to index

Description

Apply Toyota Production System pillars to AI agent workflows. Stations: triage/signal → specify → implement → test/verify → review → deploy → monitor. Jidoka: agents detect abnormalities (failed tests, invariant violations, scope creep, security issues) and STOP (pull the Andon cord), preventing defect propagation. Quality at source rather than end-of-line inspection. Just-in-Time pull based on validated intent. WIP limits. Continuous Kaizen on prompts, skills, guardrails, and evaluation harnesses.

Manufacturing Parallel

Jidoka (automation with a human touch) stops the line on abnormality. Andon signals for help. Prevents producing more defects. Proven to raise quality and flow in manufacturing.

Adversarial Assessment

Pros: Builds reliability into the process. Prevents cascade of bad AI-generated code (critical for continuous streams). Aligns with poteto: constraints make the easy path the correct one. Reduces rework waste. Supports progressive autonomy. Proven manufacturing discipline transferable.

Cons / Risks: May over-stop on false positives leading to alert fatigue. LLM non-determinism makes perfect abnormality detection hard. Can slow velocity if thresholds too strict. Human bottleneck on Andon responses. Less suitable for pure exploratory/creative work without clear quality criteria.

Viability: Strong for mature codebases with solid tests and invariants. Essential quality control layer. Medium risk of initial friction.

Team Adversarial Vote: Highly recommended. Core practice for any agent-heavy workflow. Tune carefully to balance flow and quality.
