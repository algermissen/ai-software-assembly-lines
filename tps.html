Architecture Overview

Stations as specialized agents or services with explicit quality checks that can halt flow (Jidoka). Central or choreographed orchestration. Andon events escalate to humans. WIP limits enforced at each station. Kaizen loop updates guardrails from defect data.

Stations: Intent/Spec → Plan → Implement → Verify (tests/lint/security) → Review → Deploy → Monitor. Each can STOP and signal.

Technology Choices

  • Orchestration: Temporal (durable workflows, excellent for long-running agent sessions with human waits) or Camunda (BPMN for auditable processes, strong governance). Lightweight alternative: pure event choreography on the UDN bus + state machine in code.
  • Agents: Frameworks supporting tool use and structured output (LangGraph, CrewAI, or custom with Anthropic/OpenAI agents). Instrumented with OpenTelemetry gen_ai conventions.
  • Quality Gates: GitHub Actions / custom runners for deterministic checks; secondary agents for semantic review. Policy as code (OPA/Rego or custom rules).
  • Andon: Events published to namespace → routed to Slack/Teams/PagerDuty with context (trace_id, work_order, failing check). Human response publishes resolution event that resumes workflow.
  • WIP Control: Queue depths monitored; orchestrator refuses new work above limits.

Defined Datapoints & Metrics

  • Per station: arrival_time, start_time, end_time, outcome (pass/stop/fail), defect_type, confidence_score, tokens_consumed, human_interventions.
  • Andon metrics: stop_count, mean_time_to_resolution, false_positive_rate, root_cause categories.
  • Flow metrics: WIP per station, cycle time (intent to deploy), first-pass yield, rework loops.
  • Kaizen inputs: every stop generates a candidate countermeasure (new test, prompt improvement, skill update) tracked to closure.

Development / Operations Process Flow

  1. Validated intent pulled (JIT) into Plan station. Agent or human produces structured plan + acceptance criteria. Publishes plan.ready or andon if incomplete.
  2. Implement station (coding agent) consumes plan, generates code/tests in sandbox/branch. Continuous intermediate events. On invariant violation or low confidence → STOP + Andon.
  3. Verify station runs automated suite + static analysis + security. Failures trigger immediate Andon; do not proceed.
  4. Review station (human or specialist agent) only for higher-risk or failed auto-checks. Approval publishes review.passed.
  5. Deploy station (only if all prior stations green). Progressive darkening decides auto vs human gate.
  6. Monitor station watches production signals; anomalies feed back as new intents or Andons.
  7. Every defect → Kaizen ticket: update skill, add regression test, tighten guardrail. Process improves over time.

The line stops at the first abnormality rather than propagating bad code. Humans intervene only when needed. Continuous improvement is data-driven from the stops.
