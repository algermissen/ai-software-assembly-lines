Architecture Overview

Event-driven semantic hierarchy acting as the real-time single source of truth. All producers (GitHub, CI, agents, observability, humans) publish CloudEvents or structured payloads to hierarchical topics. Consumers (agents, MES, dashboards, SPC) subscribe selectively. No point-to-point integrations.

[Producers] → [Event Bus: NATS JetStream / EMQX MQTT / Kafka]
   Topics: org/{org}/team/{team}/repo/{repo}/event/{type}/...
   → [Consumers: Agents, Orchestrators, Metrics, Dashboards]

Hierarchy inspired by ISA-95: Enterprise → Site/Team → Area/Repo → Line/PR or Issue → Cell/Step.

Technology Choices (2026 practical)

  • Event Bus: NATS JetStream (low latency, simple ops) or EMQX MQTT (UNS familiarity, retained messages for current state). Kafka for high-volume replay needs. Bridge GitHub/Linear/Jira webhooks via lightweight ingest.
  • Payloads: CloudEvents 1.0 + custom data schema. Include correlation_id, work_order_id, agent_session_id, prompt_hash, model_version, confidence.
  • Observability: OpenTelemetry (gen_ai.* semantic conventions) for traces; link via trace_id in namespace.
  • Storage/History: Event log retention in JetStream/Kafka; materialize current state to ClickHouse or Postgres.
  • Security: Topic ACLs, mTLS.

Defined Datapoints & Metrics

  • Event fields: timestamp, topic, event_type, payload (diff_size, tokens_used, test_results, quality_score), lineage.
  • Namespace metrics: publish rate, consumer lag, topic depth, schema compliance rate.

Development / Operations Process Flow

  1. Human or product system creates validated intent → publishes intent.created.
  2. Orchestrator/MES subscribes, creates production order, publishes order.scheduled.
  3. Agent stations subscribe, pull work, publish progress events continuously.
  4. Quality gates subscribe to code.proposed, run checks, publish pass/fail.
  5. On abnormality, publish andon.triggered; flow pauses.
  6. Successful deploy publishes deploy.completed; runtime telemetry flows back.
  7. All history retained for genealogy and SPC.
